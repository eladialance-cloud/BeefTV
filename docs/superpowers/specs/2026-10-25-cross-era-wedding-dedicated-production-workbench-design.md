# 跨时空婚礼电影独立制作台设计

日期：2026-10-25
状态：制作台、项目设定、朝代规划、定妆照、场景首帧和视频导演已完成；包装制作与成片交付待实施
范围：将 `/wedding/:canvasId` 恢复为唯一制作入口，并把七阶段从状态展示改造成真实执行流程
替代：`2026-10-25-cross-era-wedding-producer-workbench-design.md` 中的画布内嵌模式

## 实施状态（2026-10-25）

已完成并验证：

- `/wedding/:canvasId` 是唯一正常制作入口，画布内不再显示制作台按钮或覆盖层。
- 项目设定可保存人物称呼、故事、画幅、分辨率和授权，并执行精确下游失效。
- 朝代支持 2–5 个、排序、删除和补齐四类节点。
- 定妆照按朝代批量提交真实图片任务，使用原照片参考图，支持版本、逐人确认和阶段门控。
- 场景首帧按朝代提交真实图片任务，使用已确认男女定妆照，支持版本、自动 QC 和人工覆盖。
- 视频导演保留完整提示词编辑，生成任务携带男女肖像、场景首帧和提示词覆盖，支持版本、自动 QC 和逐朝确认。
- 场景与视频单项失败不阻塞其他朝代。

仍未实施：

- 包装制作、标题卡、BGM 和时间线预览。
- FFmpeg 正式成片渲染、整片 QC、MP4 保存和交付导出。

## 目标

制作方从首页选择“跨时空婚礼电影”后，直接进入独立制作台完成全部七阶段。画布只作为底层项目、节点、素材、任务和版本的存储层，正常制作过程中不需要进入画布。

制作台中的每个阶段都必须能执行真实动作、调用现有生成任务、展示真实状态，并在人工确认后推进。

## 非目标

- 不在画布顶部增加“制作台”入口。
- 不在画布主区域覆盖制作台。
- 不建设新人端或客户审片端。
- 不复制一套新的模型调用、资源存储或任务系统。
- 不把静态摘要、模拟进度或演示数据当作真实生成结果。

## 信息架构

页面路由：`/wedding/:canvasId`

页面外壳：

- 左侧：七阶段导航，显示状态、完成数量、阻塞原因。
- 顶部：项目名称、自动保存状态、当前阶段、返回首页、查看底层画布。
- 中央：当前阶段的真实工作区。
- 右侧：当前朝代或资产的检查器，包含提示词、参数、版本、质检和重试。
- 底部：当前阶段主操作，包括保存、批量生成、确认本阶段和查看失败项。

“查看底层画布”只作为高级修复入口，不作为正常制作流程。

## 七阶段

### 1. 项目设定

可见控件：

- 新郎、新娘照片
- 称呼
- 爱情故事
- 照片授权
- 画幅
- 分辨率

真实动作：

- 上传并登记资源
- 保存 `weddingProduction.source`
- 校验照片、授权和输出规格

门控：

- 两张照片均已完成资源登记
- 授权已确认
- 必填字段完整

失效：

- 更换人物照片：全部朝代肖像、场景、视频、包装和成片失效
- 修改故事或输出规格：场景、视频、包装和成片失效

### 2. 朝代规划

可见控件：

- 2–5 个朝代
- 朝代顺序
- 每个朝代主题、故事概述和预计时长

真实动作：

- 将选中朝代映射为现有动态节点
- 保存朝代顺序
- 为新增朝代补齐肖像、场景和视频节点

门控：

- 朝代数量合法
- 每个朝代四类节点齐全

失效：

- 新增朝代只初始化该朝代
- 删除朝代让包装和成片失效
- 调整顺序只让成片失效

### 3. 定妆照

每个朝代展示男方和女方：

- 原始照片
- 当前定妆照
- 生成状态
- 历史版本
- 人工确认状态

真实动作：

- 批量生成所有缺图肖像
- 单张重生成
- 选择版本
- 确认人物身份和服饰

门控：

- 每个选中朝代的男女肖像均已选定并确认

失效：

- 修改某朝代肖像：该朝代场景、视频、包装和成片失效

### 4. 场景首帧

每个朝代展示：

- 男女肖像参考
- 双人场景首帧
- 场景提示词摘要
- 自动 QC
- 历史版本

真实动作：

- 批量生成场景
- 单朝重生成
- 选择版本
- 自动 QC 后允许制作方覆盖硬性失败并填写原因

门控：

- 每个朝代都有选定场景
- QC 硬性项通过，或存在明确覆盖记录

失效：

- 修改场景：该朝代视频、包装和成片失效

### 5. 视频导演

每个朝代展示：

- 中文导演稿
- 完整英文模型提示词
- 参考肖像和场景首帧
- 视频模型、时长、画幅、分辨率、seed
- 生成状态、历史版本和自动 QC

真实动作：

- 保存提示词覆盖
- 恢复默认提示词
- 生成视频
- 单朝重生成
- 选择版本
- 人工确认视频

门控：

- 每个朝代均有选定并确认的视频

失效：

- 修改提示词或视频：当前朝代视频和成片失效

### 6. 包装制作

可见控件：

- 片头文案和时长
- 片尾文案和时长
- 朝代标题
- 字幕
- 转场
- 自动 BGM、上传 BGM 或关闭

真实动作：

- 生成标题卡
- 生成或上传 BGM
- 创建时间线预览
- 保存预览版本

门控：

- 包装素材完整
- 时间线预览成功
- 制作方确认预览

失效：

- 包装变化只让最终成片失效

### 7. 成片交付

真实动作：

- 创建最终时间线渲染任务
- 显示渲染进度
- 完成整片 QC
- 保存正式 MP4
- 下载成片
- 导出片段、参数、seed、提示词版本和 QC 记录

门控：

- 渲染任务成功
- 成片可完整播放
- 制作方最终确认

## 状态机

每个阶段和每个真实资产使用以下状态：

- `not_started`
- `ready`
- `generating`
- `needs_review`
- `approved`
- `failed`
- `stale`

推进规则：

- 用户可以在阶段间查看，但“确认本阶段”必须通过门控。
- 阶段完成后记录 `approvedAt`。
- 上游变化只让准确的下游范围失效。
- 批量任务中单个朝代失败时，其他朝代可以继续审核。
- 失败项提供“重试当前项”和“查看全部失败”。

## 真实任务接入

制作台不创建第二套任务系统。

肖像、场景和视频节点继续使用：

- `CanvasNodeData` 的节点 ID 和 metadata
- 现有 `runBackendGenerationTask`
- 现有任务订阅、结果物化和资产修复
- 现有 `persistCanvasDocument`

实现边界：

- `use-wedding-workbench-runtime` 负责阶段动作和任务状态同步。
- `wedding-production-service` 负责批量映射节点、提交任务、消费结果和更新 `weddingProduction`。
- 阶段组件只负责交互和展示，不直接拼装模型协议。
- 服务端继续通过模板、节点和朝代解析私有提示词。
- 制作方提示词覆盖继续通过 `promptOverride` 传给服务端。

任务步骤映射：

- 肖像：`dynastyPortraitMale`、`dynastyPortraitFemale`
- 场景：`dynastyScene`
- 视频：`dynastyVideo`
- 包装：时间线和音频节点
- 成片：现有时间线本地渲染

- `/canvas/:canvasId?canvasView=wedding` 只做兼容跳转到制作台

- 移除画布模式下隐藏节点工具栏的特殊逻辑

## 错误处理

- 资源上传失败显示具体文件与阶段，不写入半成品。
- 任务提交失败保留原状态和重试入口。
- 任务轮询断线后从任务中心恢复，不重置已完成版本。
- 结果物化失败保留任务 ID，并提供重新同步。
- revision 冲突停止覆盖，要求重新加载项目。
- 渲染失败保留时间线和中间文件，允许重新渲染。
- 保存失败不得显示“已保存”。
- 提示词预览失败时禁止静默使用空提示词。

## 验收标准

- 用户正常制作时只使用制作台，不需要进入画布。
- 画布只用于底层修复和高级查看。
- 七个阶段均有真实动作，不再是静态摘要。
- 所有模型生成使用现有任务链并显示真实状态。
- 每个阶段必须人工确认后才能推进。
- 单个朝代失败不会阻塞其他朝代。
- 旧的跨时空婚礼项目可以进入制作台并自动补齐生产状态。
- 前端构建、专项测试、浏览器测试和后端相关测试通过。
